# STRICT STRUCTURE RULES

## RULE 1: SECTIONS
- If the question paper has no explicitly labeled sections, treat the entire document as a single section with `sectionId: "section_1"`.

## RULE 2: PARENT VS. CHILD TEXT SEPARATION (NO TEXT DUPLICATION)
- STEM / INTRO TEXT ONLY FOR PARENTS: The `text` field of a parent question (e.g., `Q33`) MUST ONLY contain introductory text, passages, context descriptions, or general instructions that apply to all child sub-questions (e.g., "Study the fixture given below and answer the following:").
- NEVER include sub-question prompts, sub-question numbers (a, b, c, d), or sub-question choices inside the parent's `text` object.
- SUB-QUESTION TEXT IS ISOLATED TO CHILDREN: The actual prompt for each sub-question (e.g., Q33.a, Q33.b) MUST live EXCLUSIVELY inside its respective child node in the `children` array.
- EMPTY PARENT TEXT: If a parent question node has NO introductory stem text or context instructions of its own on the page, Omit the text.en and text.hi keys for that question.
- NEVER make children's array empty if sub-questions of a question exist. Never put subquestions in options array.
- If no subquestions exist, make children array empty. ("children": [])

## RULE 3: PARENT TEXT BOUNDARY
- Parent text exists ONLY when there is actual shared text/context written before children (e.g., Paragraphs, Case Studies, or general instructions).

## RULE 4: ATTACHMENT PLACEMENT
- Attachments belong strictly to the lowest relevant question node where the visual is referenced. Never move them upward to a parent node unless the visual applies to all sub-questions.

## RULE 5: VISUAL & ATTACHMENT EXTRACTION
- MANDATORY DESCRIPTION KEY: An attachment object consists of EXACTLY TWO REQUIRED KEYS: `"type"` and `"description"`.
- Lossless Natural Language Description: `description` MUST capture every coordinate, variable, label, vector, text snippet, and data point shown in the visual so an evaluator can grade the question without seeing the original image.
- STRICT PROHIBITION ON TEXT FIELD DUMPING: Put 100% of visual descriptions inside `attachments[].description`. NEVER write "Image-1:" or descriptions inside `text.en` or `text.hi`.
- Use simple english language in the description string. The type key must only contain one of the following ("MCQ", "MTF", "Theory", "Hybrid").
- VISUALS INSIDE OPTIONS OR MTF COLUMNS: If an option (MCQ) or column item (MTF) contains an image, DO NOT create an `attachments` object. Instead, put the full lossless description directly inside the language tags (`en`/`hi`) of that option/item object.

## RULE 6: CHOICE & "OR" PAIRING
- STANDALONE "OR" PAIRING: When an "OR" separator appears standalone between two question blocks, it creates a choice strictly between the block immediately BEFORE it (Predecessor) and the block immediately AFTER it (Successor).
- Visual Verification Check: Locate the physical word "OR". Or check the parent text or section instruction if it has text like ("Attempt any 3", "Answer any two" etc).
- Marks Validation Check: For any standalone "OR" choice between two questions (e.g., Q2 OR Q3), both questions MUST have the exact same `extractedTotalMarks` value.

## RULE 7: CHOICE SCOPE BOUNDARIES
- `sectionChoices`: Use inside a section object for choices between Level 1 questions (e.g., Q1 OR Q2).
- `choiceInformation`: Use inside a question object ONLY when a choice is confined strictly to its immediate sub-question children (e.g., Q1.a OR Q1.b, Q1.i.a OR Q1.i.b etc).
- `globalChoices`: Use ONLY at the root document level for choices strictly between independent SECTIONS.

## RULE 8: HIERARCHY
- Maintain a strict hierarchy (Level 1 `Q1` -> Level 2 `Q1.a` -> Level 3 `Q1.a.i`).
- Intermediate levels without text must use empty strings `""` inside their language keys.
- Level 3 nodes do not support a `children` key.

## RULE 9: INTACT UNREADABLE TEXT
- Never invent missing text. If unreadable, add a clear note in `parsingStatus.warnings` (e.g., "Question 5 image unclear").

## RULE 10: INLINE LABELS AND PREFIXES
- Do not create intermediate, content-less parent nodes out of hanging execution phrases (e.g., "Calculate:", "Find:", "Given:"). Include such introductory words in the parent node's `text` field.

## RULE 11: DIAGRAM REQUIRED FLAG
- Set `diagramRequired` to `true` ONLY if the question explicitly commands the student to draw or plot a visual artifact using action verbs like "Draw", "Construct", "Plot", "Sketch", "Graph".
- If the question merely references an existing diagram provided on the page (e.g., "Refer to the circuit diagram below..."), set `diagramRequired` to `false` if no visual is asked to be drawn.

## RULE 12: READING PASSAGES & COMPREHENSION TEXTS
- Treat the ENTIRE body of a reading passage or case study strictly as part of the parent question's `text` object.
- PRESERVE PARAGRAPH LABELS: Do NOT convert numbered or lettered paragraphs (e.g., "(1)", "(2)", "A)", "B)") inside a passage into child sub-questions.
- Critical Paragraph/Extract Summary Rule: For long paragraphs summarize the text and write them in the parent question's `text` object such that it covers all the main points which may be asked in the subquestions of that paragraph and does not exhaust the output tokens.

### RULE 13: CRITICAL RULE- Sub-Questions & MCQ Options
 - DO NOT generate dummy sub-questions, options, or choices if they do not exist in the source document.
 - If a question is not multiple-choice, leave the `options` key omitted rather than generating empty objects.
 - For choice tasks (e.g., "Attempt ANY 10 of 12"), strictly structure `choiceInformation` and list only the existing choices without inventing extra fields.
 - Do not treat sub-questions as mcq options and mcq options as sub-questions both are different fields.
 - For Writing Skill questions like ("Write a paragraph","Write a notice" etc) Do not treat them as options. Treat them as subquestions. DO NOT USE "..." to finish text early.

## RULE 14: MATCH THE FOLLOWING (MTF)
- Set `type` strictly to "MTF" when matching two lists/columns.
- Populate `matchData` containing `matchFrom` and `matchTo` arrays with bilingual text objects.
- Do NOT duplicate column text inside the question's main `text` field.

# JSON FIELD DEFINITIONS

- paperMetadata: Object containing general metadata.
- instructions: Object containing instruction arrays mapped by language keys (`en`, `hi`).
- parsingStatus: Object containing:
  - success: Boolean (`true`/`false`).
  - paperClarity: String (`"clear"`, `"partially_clear"`, `"unclear"`).
  - errors: Array of critical execution error strings.
  - warnings: Array of non-fatal warning strings.
  - extractedRisks: Array containing exactly 3 string items identifying edge cases or ambiguities.
  - confidence: Number (0–100) representing overall structural accuracy.
- sections: Array containing section objects:
  - sectionId: Unique string ID in lower-case snake_case (e.g., `"mathematics_section_1"`). Defaults to `"section_1"` if unlabelled.
  - sectionChoices: (Optional) Array of choice objects between Level 1 questions inside this section.
  - sectionInstructions: Bilingual object mapping section-specific instructions (`en`, `hi`).
  - questions: Array of Level 1 question objects inside this section.
- type: String enum (`"MCQ"`, `"MTF"`, `"Theory"`, `"Hybrid"`).
- id: String representing question hierarchy (e.g., `"Q1"`, `"Q1.a"`, `"Q1.a.i"`).
- text: Object containing question text mapped by language keys (`en`, `hi`).
- marks: String representing node marks.
- extractedTotalMarks: (Level 1 parent nodes only) Printed total marks for the entire main question block (e.g., `"10"`). Omit this key entirely on Level 2 and Level 3 nodes.
- rubric: Always return an empty array `[]`.
- attachments: (Optional) Array of visual objects (`type`, `description`).
- diagramRequired: Boolean (`true`/`false`).
- children: (Optional) Array of sub-question objects.
- options: (Optional) Array of MCQ choice objects (`optionId`, `text`). May be listed using ( i), ii), iii), iv) or a), b), c), d) or A), B), C), D) etc).
- matchData: (Optional) Object containing `matchFrom` and `matchTo` arrays for MTF questions.
- choiceInformation: (Optional) Choice object for choices between immediate sub-question children.
- globalChoices: (Optional) Root-level array of choice objects between sections.
